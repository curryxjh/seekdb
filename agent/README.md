# 学习材料与证据边界

唯一参评输入是 `agent/conversation.json`；本文件不作为评分证据。

2026-11-13 性能迭代：从 `cefca4665498c5c20e1f85ca4201190e3434499c`
创建 `minivectordb-perf5000`。保留已有学生原话、实例及历史实验，历史实验不再
标为当前源码验证。追加真实优化请求、Agent 工程总结、当前源码本地配对结果和
验证输出；本轮没有新增学生学习实例。用户仅提供基线约 2500 总分，5000 目标
尚无平台验证。摘要对应 Git 中的 LF 文件；当前报告见 `docs/perf5000.md`。

本轮对材料做了结构调整：保留关键历史反馈，将新的用户原话、Agent 解释、
实际验证输出分开，提供可定位的 JSON pointer 和精确摘录。删除重复历史日志，
保留材料精简说明，控制在 UTF-8 128 KiB 限制内。

本轮已发生的学习链是过滤 TopK：用户预测“先过滤”，看到反例后提出疑问，
澄清后解释了过滤集合与 LIMIT 上限，并预测 LIMIT 200 应返回 100 条。
迁移实验实际返回 100 条。这些阶段属于同一个实例，不能拆分重复计分。

另保留了用户对“提前刷页不等于事务提交”的解释与确定性强杀验证，以及对
“有损表示安全剪枝不等于直接按量化距离取 K 条”的解释与量化并列反例。
问题由 Agent 引导，程序和实验由 Agent 实现；材料不把这些来源改称学生自主发明。
实例划分用于组织证据，是否需要语义合并、适用哪个档位仍由官方评审判断。

用户对省略 fsync 的拒绝，以及对不能宣称平台已经提高三倍的判断，也保留原话。
没有提供的技术理由不由 Agent 补写成学生发言。性能优化、误差界推导、测试设计和
自动实现仍归 Agent；不能凭工具日志把这些工作改称学生理解。

材料校验：

```sh
python3 tests/evidence.py
```

检查合法 JSON、重复键、非标准数值、128 KiB、引用原文、学生来源、跨实例重复引用、
结果与学生证据分离、源码摘要和随附产物摘要。该工具不模拟官方评分，不预测名次。

五个维度的更高分需要后续真实理解和验证，尤其是解释实验原因、修正方案、
迁移场景和分析代价。`learning_opportunities` 明确列为尚未完成的学习机会，
不得将其当成已经执行的学习实例。
