# 2026-11-13 性能优化与交付记录

基线为 `codex/minivectordb-round2-optimize` 的
`cefca4665498c5c20e1f85ca4201190e3434499c`，开发分支为
`minivectordb-perf5000`。用户仅提供基线约 2500 的平台总分，未提供
T/B/M 明细。5000 是目标，本轮没有发起平台评测，也没有达到该分数的证据。

## 改动及正确性边界

1. 将每次提交的外部 catalog 写入、同步、重命名及目录同步，改为向现有
   data 文件追加 catalog 和 56 字节提交尾记录，再执行一次 `fsync(data)`。
   保留 COW 根、语句回滚、显式事务和提前刷页机制。校验覆盖 catalog 和本次
   新增数据；同步成功后才响应成功。新建目录/首次迁移仍需同步格式保护文件及目录。
2. 原始向量缓存由固定 8 MiB 改为可见内存限制的 1/8，下限 1 MiB、上限
   128 MiB；量化辅助数据预算为其一半。读取 cgroup v2 当前组及祖先限制，
   也读取常见 v1 限制文件。缓存只保存有界前缀，其余记录继续精确流式扫描。
   写入、回滚、失败语句和切换表时释放缓存容量。
3. 在支持 AVX512F/BW/VNNI 的 CPU 上，四条记录共享查询加载，使用 VNNI
   字节点积计算筛选距离。尾维度采用掩码加载；无相应指令集时使用既有
   AVX2/ARM/标量路径。量化只用于保守筛选，结果仍以原始 float32 精确复核。

恢复按重叠 1 MiB 块向后查找完整提交，按 64 KiB 块校验新增数据，拒绝
不完整的尾记录/载荷并截断未提交尾部。进程强杀与损坏模拟不能代替真实断电验证。

旧格式目录可以读取，并在首次新提交时升级。新提交持久化后，外部 `catalog`
改写为格式保护标记，阻止旧二进制误截断新数据。升级后不能直接用旧二进制降级；
需要保留升级前备份。本轮没有提供逆向格式转换器。

## 最终源码的本地配对结果

环境：WSL2 Ubuntu、Linux x86_64、Intel i5-11260H、原生 GCC 13.3。
基线与候选均通过相同 `build.sh` 构建。每个版本/种子使用新 service cgroup，
CPUQuota=200%，swap=0；Python 驱动和独立 float32/math.dist 真值在组外。
种子为 20261113、8675309、14223819，中间一轮逆序执行。

| 负载 | 内存限额 | 写入加速中位数 | 查询加速中位数 |
| --- | --- | --- | --- |
| 10000 行，128 维，500 次查询 | 128 MiB | 1.822× | 1.177× |
| 50000 行，128 维，200 次查询 | 2 GiB | 1.806× | 4.693× |

查询各半为无过滤/普通列等值过滤，K=10；每批 100 条插入并提交。
所有查询逐条检查 ID、顺序和距离，过滤与无过滤 Recall 均为 1，并重启核对内容。
查询耗时在首次查询和 10 次预热后测量；写入耗时包括持久化响应。
资源峰值包含所在进程启动、写入、首次查询与预热，不能视为纯查询增量内存。

5 万行三轮查询耗时分别从 645.14/661.16/646.76 ms 降至
137.47/172.94/136.61 ms。但首次查询约从 25 ms 增至 60 ms，查询阶段
内存峰值约从 46 MiB 增至 68 MiB。1 万行查询收益明显较小。
嵌入 catalog 使 data 文件增大约 0.29%。当前格式仍保留历史 COW 页和提交记录，
没有压缩回收；大事务恢复校验耗时与该次新增字节数有关。

本机未委派 IO controller，`io.stat` 和 `proc_io` 均为 null。
data 文件长度不是块设备 I/O 指标 B；本轮不能计算官方 E，也不能把本地加速倍数
换算成平台分数。AVX512 收益还取决于评测 CPU。上述总改动的对照没有分项消融，
不能将整体收益分别归因到每项改动。

## 验证结果与限制

未修改官方驱动、公开断言、协议和 Docker 配方。最终源码通过：

- 官方公开驱动 20/20 用例、95 SQL，以及协议、5 种子随机回归、缓存、浮点数、
  维度扫描、筛选和三种顺序的 B+ 树分裂检查。
- 生产与 ASan/UBSan 构建验证；量化区间检查 27305 项，包含尾维度和极值。
- 既有提交强杀/重复恢复检查；新增提交日志 124 项，覆盖逐字节截断最后
  56 字节、校验损坏、完整尾记录下的载荷损坏、多块未提交尾部及旧格式迁移。
- 大事务提前刷页后强杀、失败语句原子性；96 MiB、swap=0 下 40000 行的
  提交、索引、过滤 TopK、外部排序、回滚、删除提交、SIGKILL 和恢复。
- 额外 32 MiB 限额下缓存用例 41 项，包含缓存前缀之外的获胜结果。

Docker Desktop 本轮未成功启动；清理其失效 `dockerInference` socket 的请求被
自动审批以 “blocked by policy” 拒绝，未继续该操作。使用原生 Linux cgroup 完成了
替代验证，但本轮实际镜像构建和容器运行仍未验证。Dockerfile 固定 GCC 14.2，
与本地 GCC 13.3 不同。历史容器结果属于历史源码，不作为本轮镜像通过证据。

## 复现

在干净 Linux 检出目录运行，源码须保持 Git 中的 LF；Windows 导出可使用
`git -c core.autocrlf=false archive`。准备独立基线目录和候选目录，各执行
`sh build.sh`。需要可用的 systemd 用户管理器、memory controller，允许缺少
IO controller（缺失将明确记为 null）。在候选目录执行：

```sh
python3 tests/native_cgroup_benchmark.py \
  --baseline ../baseline/build/minivectordb --candidate build/minivectordb \
  --rows 10000 --dimension 128 --queries 500 --memory 128M --output native-10k.json
python3 tests/native_cgroup_benchmark.py \
  --baseline ../baseline/build/minivectordb --candidate build/minivectordb \
  --rows 50000 --dimension 128 --queries 200 --memory 2G --output native-50k.json
python3 tests/native_resource.py --binary build/minivectordb --output resource-96m.json
```

完整验证可在基线目录为 `../baseline` 时执行以下命令；该脚本为实际运行脚本原件，
会生成本地结果文件并在首个失败处退出：

```sh
sh build.sh
python3 docs/results/perf5000-run_validation.py
python3 tests/evidence.py
```

材料保留已有学生原话与学习实例，只追加本轮真实请求、Agent 工程工作和验证输出。
本轮自动实现不新增学生学习实例，不自评 Agent 分，也不声称平台已达 5000。
