截图中的性能计算以 `R_T=(T_base+1ms)/(T+1ms)`、I/O 与内存分别加 `1MiB`
平滑，再用 `f(R)=R/(1+R)`；写入与查询分别计算
`0.6f(R_T)+0.2f(R_B)+0.2f(R_M)`，合并为 `(E_write+2E_query)/3`。
本地比较器把旧版本当参考，只用于筛选实现，**不是组织方 E**。不能将
`5300/3486.1987` 当作所需吞吐倍数。

## 最终保留：省去向量数字的重复扫描

`vector_literal()` 原先逐字符找到数字末尾，再让 `from_chars<double>` 重读数字。
现在由 `from_chars` 直接读取剩余数组文本，通过返回指针推进位置，再检查分隔符。
保留前导 `+` 处理、极小数的 `strtod` 回退、严格十进制语法和
decimal → double → float 的原有舍入过程。

生产代码仅有 `minivectordb/sql.cpp` 的这一处增量。没有增加配置或依赖。
官方协议、驱动、SQL 用例和断言没有差异；提交确认和 exact 结果语义没有调整。

### Linux amd64 生产容器三轮相邻对照

基线为起点提交对应镜像 `minivectordb:perf5000-candidate-5572448`。
每轮 10000 条 128 维数据、每批 100 条写入、1000 条不同 Top10 查询，
一半查询有普通列过滤。独立容器和数据卷，2 CPUs、128 MiB、swap=0、断网，
10 条预热查询；中间一轮颠倒旧/新顺序。每条结果在计时外检查 ID、顺序、
距离和独立 float32/math.dist 真值；写入另检查重启后的完整内容。

| seed | 旧版写入 ms | 新版写入 ms | 旧版查询 ms | 新版查询 ms |
|---|---:|---:|---:|---:|
| 20261112 | 1727.977 | 1677.935 | 483.073 | 489.652 |
| 39034843 | 1657.846 | 1712.282 | 490.276 | 488.181 |
| 774193 | 1692.435 | 1612.572 | 524.412 | 461.167 |

查询逐种子加速比中位数为 **1.004293×**，不是显著提速证据。
写入耗时中位数为 1692.435 → 1677.935 ms，约减少 0.86%，但第二轮变慢。
所有结果精确召回均为 1。各轮原始 I/O 都是 6,848,512 bytes；共享设备的
写回归属未经组织方认证。查询峰值内存中位数为 25,063,424 → 22,671,360 bytes，
实现没有改变缓存布局，不能据此归因于解析器或宣称稳定内存优化。
逐轮 T/B/M 合成的本地代理中位数为 0.503104（同版参考为 0.5），不换算平台分。

Apple M4 Pro 本机构建的独立初筛中，三轮写入均减少约 3%–6%，600 条查询的
成对加速比中位数为 1.022264×。生产 Docker 在 Apple Silicon 上模拟 amd64，
收益明显更小，因此不采用本机更好的数值作为交付结论。

## Prompt 材料的实质修正

原材料约 126 KiB，但 `metadata.source_sha256` 仍指向旧源码，
成绩仍为 3177.969535/5.5，旧实验与当前源码的描述有冲突。这些已纠正：

- 保留原来 53 条消息、5 个学习实例和被引用的历史实验 0–3 原文；
  新增用户本轮原话，性能反馈仍并入已有同一实例，避免重复记分。
- 提供中文五维索引，引用单一 JSON 内的学生与结果字段，保留指导来源和局限，
  不要求评委采纳特定分数。
- 两份重复历史工程验证日志改为标明范围的摘要，保存原文哈希、父提交和归档。
  被引用原文仍在 JSON 内；不会依赖外部文件补足学生学习证据。
- 当前性能与验证单独记录源码身份；旧实验全部标为历史。
  完整命令日志在仓库中，JSON 内也保留必要真实结果。

| 维度 | 现有可定位证据 | 真实性边界 |
|---|---|---|
| 问题理解与自主拆解 | 用户提出目标、基线和限制 | 缺少学生自主拆解理由、预测与验证闭环，不代写 |
| 技术理解与迁移 | 过滤先于 TopK、提前刷页不等于提交、量化安全剪枝 | 明确是引导后的解释；各问题链只记一个实例 |
| 独立验证与质疑 | 学生用正式失败反驳本地通过结论，质疑准入；随后实际握手复现 | 修复由 Agent 完成，不改称学生代码贡献 |
| 实验与反馈迭代 | 实际分数涨跌反馈与“大规模首次查询仍更慢”的边界反馈 | Agent 设计执行实验；没有学生对 T/B/M 原因的解释 |
| 取舍与反思 | 学生拒绝省略 fsync、拒绝把本地倍数当平台倍数 | 这些简短回答的技术理由、对照结果分析和复测选择不完整，不单列新增实例 |

这些修改提高材料的可核对性，**不能保证 Prompt 从 5 分升到某个分数**。
更多 Agent 日志或代写“我的反思”不构成学生实际学习。

同日补录三条真实历史追问：官方驱动是否存在、公开题包版本与开发基线的区别、
规则中配套驱动的说明。消息发生于准入修复前，统一并入原准入反例实例，
引用已有失败与修复结果，不增加实例数或推断学生已独立定位握手错误。
建议 Prompt 留作新讨论草稿，不计为既有学生判断。
