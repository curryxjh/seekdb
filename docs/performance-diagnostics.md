# Exact 查询与写入性能画像：2026-11-16

本轮结论是优先验证 **int8 批量距离扫描**，暂不替换种子堆，也不实现动态 cutoff。
已经实际运行 A/A、粗粒度计时、事件计数、采样敏感性、动态界旁路观察与分配诊断。
生产查询、存储、编译选项、官方协议、驱动及断言均未修改。本轮到画像与实验设计为止。
没有正式平台重测，不能据此声称超过 5000。

## 1. 版本、工作负载与测量边界

- 分支：`minivectordb-perf5000`；调查起点：`ec29ef0a038339250a6c2bf017b50fba0680adef`。

- 生产源码摘要：`a2553e08d54269ddea41679914b7d5d03f30369ab07178f87be21f3dd66ad6d3`。
- 生产二进制 SHA256：`dc7800d5669fae8c50669b104c750b460d811ccbafe0cf10628619e3c06b5608`。
- 固定种子 `20261109`，10000 行、128 维、1000 条不同 Top10 查询；
  500 条无过滤，500 条过滤，选择率 25%。每 100 行一批自动提交，共 100 批。
- 工作负载摘要：`4482c7dca85141f589bf16445b2a7a6121273b620ff95df6e28e42294465c9f7`。
- 每个数据库容器独立数据卷、2 CPU、128 MiB、swap=0、禁网络。观察者在另一个
  原生 arm64 容器中读取数据库 cgroup 和进程状态，不向被测 cgroup 加入监控子进程。
- Apple Silicon 模拟 Linux amd64；宿主负载、文件缓存未隔离。这里的“首次”
  指完成写入后第一次建立查询缓存，不是已清空操作系统页缓存的冷盘测试。
- 实测 CPU 特性不支持 AVX2/VNNI，1000 次调用均选择 scalar fallback。
  该名称指源码回退路径，不意味着编译器没有使用基础 SIMD 指令。
  `perf_event_open` 返回 `EPERM`，没有测得 cycles、IPC、cache miss。
- 生产镜像只测外部延迟；诊断镜像只用于归因与计数。不能把诊断镜像时间当正式性能。

各目录 `identity.json` 保存命令、源码/工作负载/镜像/二进制摘要。

## 2. A/A 噪声与诊断自身的影响

先运行同一个无埋点生产二进制，A/B 相邻执行，第二对交换顺序。
以下为整个写入阶段和 1000 条稳定查询的外部累计时间，单位 ms。

| 对 | 写入 A / B | 查询 A / B | 查询 B 相对 A |
|---|---:|---:|---:|
| 0，A→B | 1671.991 / 1631.342 | 464.092 / 443.402 | -4.46% |
| 1，B→A | 1627.581 / 1632.415 | 473.468 / 510.757 | +7.88% |
| 2，A→B | 1642.495 / 1665.816 | 428.413 / 483.512 | +12.86% |

写入差异为 -2.43%、+0.30%、+1.42%。只有三对，不能据此建立可靠置信区间，
也不能把观察到的极值当作未来噪声的硬界限。当前无法分辨几个百分点的查询收益。

粗粒度诊断 B 对生产 A 的查询差异为 -9.51%、+36.91%、+4.56%。
事件诊断的三对差异为 -7.89%、+4.11%、-4.74%；分配诊断仅一对，B 慢 47.09%。
这些数据既含测量扰动，也含环境波动；没有依据宣称“零开销”或固定开销比例。
分配诊断只使用次数，绝不用其时间证明优化。

内部 `request` 计时从完整请求行读完后开始，至响应输出后结束。外部时间还包括
输入构造/JSON 编码、输入传输及组行、管道、宿主调度、响应接收/解码等未分离成本。
内部也是 elapsed time，不是 CPU cycles 或 CPU 自耗时。诊断日志写入位于内部
request 计时之外，也可能扰动下一次请求。

整数界拒绝率为 **99.67367%**，float32 对其输入再拒绝 **98.25173%**。

mmap、栈内对象、SSO 内联存储及所有库内复制。它统计累计请求，不是 live bytes：

### 动态 cutoff 的旁路结果

保持原 static cutoff 的实际决定、原向量读取和最终结果不变，仅在原本通过的
20363 个候选上重新计算当前精确堆的 cutoff：额外可拒绝 **213** 个，
占原通过数 1.0460%，占全部有效候选 0.003408%。
这些候选实际仍走原流程，没有一个改变最终精确堆。
没有统计其中多少已由 float32 拒绝，不能声称可省 213 次补偿精算。

从实数几何上，若量化重构误差上界为 E，真实距离不大于 W 的候选满足
`scale * sqrt(integer_distance) <= W + E`。精确堆始终含 K 个实际候选，
升序 W 只会收紧，因而可以产生更紧的必要条件；降序使用相反方向的下界。
实际实现还必须保留 `nextafter`、膨胀误差、整数余量及严格拒绝比较，
让距离并列仍有机会按主键排序。该论证不代替所有 IEEE 浮点边界的实现级证明。
尤其不能把数学上的真实距离、补偿 double 结果和最后 sqrt 的舍入直接混同。
本轮未实现新界，也不宣称完成了新公式对所有输入的正式证明。

## 7. 瓶颈、收益上限与重新排序

可分辨的查询前三块是 int8 批量距离、后续整数界扫描和种子选择。
第二块包括少量 float/精算/堆操作，不是纯整数比较。
写入前三个可分辨块为 fsync、尚未拆开的行/树/blob 执行、JSON+SQL 解析；
提交 checksum 也是稳定可见的成本，但小于合计解析。
向量转换、树、编码三者的精确排名缺数据，不强行编造。
两个端到端阶段的大块未归因成本另外列为测量缺口，而非虚构 CPU 瓶颈。

按“其余成本固定、该阶段完全消失”计算的本地消除上限：
int8 约节省 10.53% 外部查询时间；整数扫描整个块约 4.16%；
种子选择约 1.70%；种子复核约 1.39%；输出约 1.26%；
SQL 解析约 0.98%；初始化约 0.96%；投影约 0.59%；JSON 约 0.57%；
排序约 0.20%；量化约 0.15%；候选数组约 0.14%；暖位图查找约 0.08%。
float/补偿精算只是父块的组成部分，没有可靠独立外部上限。
首次缓存构建应使用首次的分母，不能套入暖查询占比。
写入侧 commit 合计上限 6.66%，其中 fsync 5.77%、checksum 0.64%；
非提交执行块 3.96%，解析合计 1.01%，flush 0.09%。
**这些是受扰动诊断轮的 Amdahl 估算，绝非生产程序或平台的严格性能界。**

| 2 | 整数界顺序扫描；`database.cpp` 种子后的循环 | 23.154 ms 父块；可研究编号/条件分支，不能把整个块都计作可省比较；内存/I/O 预计不变 | 原 cutoff、seed 排除、tie 条件不变；逐候选决定差分 |
| 3 | 复用 distance/rows/query codes 缓冲 | 约 61.5 次 new/query，但归因未分离；可能减少分配，保留容量会升高长期内存 | 表切换、不同维度、失败语句、回滚与超预算尾扫；先加调用栈归因 |
| 4 | 首查 int8 缓存构建与地址遍历 | 首两条中约 9.616 ms；暖查询无此成本；代码/数据布局优化需原生机器复核 | 不推迟 ready/隐瞒准备；编码/误差界逐项一致 |
| 5 | 写入节点按值复制、行编码 | 47.2 MB 已识别节点载荷复制；耗时归因尚不可靠；借用接口有生命周期复杂度 | COW、savepoint、早刷页和崩溃回滚；先解决写入测量偏差 |
| 6 | 提交 checksum 流水化 | 可见 9.208–10.510 ms；有降低重复缓存读取机会；物理查询 I/O 已为零 | 提交覆盖区、恢复验证、失败重试都不能变；当前不建议直接修改 |
| 7 | 投影/输出与解析分配 | 占比小；协议和结果文本必须不变；更长 SQL/更大结果可能不同 | typed id、Unicode、分片、spill 和异常一致；需独立重放 |
| 8 | 动态或逐行更紧的量化误差界 | 本样本仅额外 213 个候选机会；加浮点界运算可能得不偿失；不同分布待查 | 需完整舍入/极值/tie 证明；目前仅旁路计数 |
| 9 | heap、nth_element、短数组 | 种子选择仅约 1.70% 外部时间，低于已见 A/A 波动；物化可能额外用内存 | 保留种子 rank 并列规则、阈值和 Exact；本轮明确不做 |
| 10 | 暖过滤位图查找 | 500/500 命中，只有 0.462 ms；动态谓词或低命中率可能另论 | 不放宽 WHERE；当前无需优化 |

不把取消同步、改成近似返回、缩减 oracle、移动统计范围作为候选方向。
当前平台只有用户报告的总分，没有绑定此生产版本的 T/B/M、CPU 特性或统一基线；
无法从本表推算 5000。

## 8. 下一项单因素实验：仅建议，尚未实施

建议先独立验证 **连续候选 int8 fallback 的每行间接调用/调度成本**。
生产二进制反汇编保存在 `nov16-diagnostics-int8-assembly.txt`；
已确认当前连续 fallback 循环每行经过 dot 的间接调用及初始化 guard 检查。
减少这部分工作能否改善端到端时间，要以重放为准，不能只看指令数猜测。
先不改 filtered SIMD、种子堆、存储、界公式、缓存布局或编译选项。

Agent 的修改前预测及推翻条件：

1. 同一布局、相同 query codes/norms，整批直接调用 fallback 计算，可能减少调用开销。
   方向为局部 int8 时间下降；幅度无法可靠量化。若 kernel 重放无稳定改善，
   或编译器生成的指令没有减少，推翻该机制预测，停止集成。
2. 先只作用于无过滤连续 fallback。该轮这一块为 45.510 ms，
   因此即使完全消除，整体外部暖查询上限约 8.18%；整个 int8 块上限约 10.53%。
   不能承诺跨过当前 A/A 噪声，更不能承诺平台 5000。
3. 不增加分配、容量和文件操作，预计写入和物理 I/O 不变；
   cgroup 峰值预计无可分辨变化。稳定增加分配/容量、I/O 或写入退化都反驳预测。
4. int8 code 在 [-127,127]、D≤4096，点积绝对和≤66,064,384，
   最终平方距离≤264,257,536，均在 int32 范围。
   只重排这些精确整数计算且所有中间值均有界，可以保持结果逐位一致，
   不必触碰浮点误差、原向量、最终距离和并列规则。
   任一 integer distance 或 TopK ID/顺序/数值摘要不一致立即拒绝。
5. 正式机器若走 AVX2/VNNI，该 fallback 修改可能完全没有效果；
   本地模拟成功也只构成进入原生复核的理由。

最小顺序：先保存生产基线二进制；诊断缓存导出固定代码/编号/查询输入，
在无时钟内循环中批量重放，多次交换先后次序；kernel 正确且收益可重复，
才提议只修改该函数，并用无埋点生产构建做至少 6 对相邻 AB/BA，
保留预先固定的种子、顺序、编译参数、首查/暖查询和过滤分组。
用配对比值、分布及 A/A 同期数据判断，不以某次最快结果验收。
若差异仍低于波动，报告“证据不足”，不进行累计试错直到偶然跑快。
若 kernel 没有收益、发生正确性差异或资源超限，立即停止该方向。
更大规模、更多维度和原生 amd64 应在单因素成立后分别扩展，不同时改变矩阵。

仍缺：正式机器 CPU/分项指标、隔离主机的端到端时序分解、写入可靠细分、
分配调用栈、动态界通过者中实际精算数、新分布/低命中谓词和冷盘数据。
本轮没有运行下一项算法实验；保留用户对结果的解释、是否接受取舍及迁移判断为待讨论。

其 `/cg/docker/<container-id>` 路径及架构在其他宿主需要先核对。

进程快照和重启记录。聚合文件为 `nov16-diagnostics-summary.json`，
分析脚本校验事件恒等式及跨构建 Exact 数值/顺序摘要。

官方 x86 built-in 接口。实测数据来自本仓库运行记录，非外部资料。
